### BUG-002: Неправильный импорт logger в CSRF middleware
**Файл:** `backend/src/middleware/csrf.ts` (строка 9)  
**Влияние:** Backend не скомпилируется. TypeScript выдаст ошибку "Cannot find module". Сервер не запустится.  
**Описание:** Указан неправильный путь импорта: `import logger from './logger.js'`. Файл logger.ts находится в `backend/src/services/`, а не в `middleware/`.  
**Решение:** Исправить путь импорта на `'../services/logger.js'`.

```typescript
// Неправильно:
import logger from './logger.js';

// Правильно:
import logger from '../services/logger.js';
```

### SEC-005: Пустая строка в CSP директиве imgSrc
**Файл:** `backend/src/index.ts` (строка 35)  
**Влияние:** Потенциальная уязвимость CSP. Пустая строка может позволить загрузку изображений из непредусмотренных источников.  
**Описание:** В Helmet конфигурации содержится пустая строка в массиве imgSrc: `["'self'", "", "https:", "http:"]`.  
**Решение:** Удалить пустую строку из массива imgSrc.

```typescript
// Неправильно:
imgSrc: ["'self'", "", "https:", "http:"]

// Правильно:
imgSrc: ["'self'", "data:", "https:", "http:"]
```

### BUG-003: Порядок middleware CSRF и маршрутов
**Файл:** `backend/src/index.ts` (строки 89-90)  
**Влияние:** Потенциальная проблема с получением CSRF токена. При изменении порядка или логики middleware может сломаться получение токена.  
**Описание:** CSRF middleware применяется ко всем /api маршрутам, включая /api/csrf-token. Хотя GET-запросы проходят, порядок маршрутов может вызвать проблемы.  
**Решение:** Переместить маршрут /api/csrf-token ДО применения CSRF middleware или исключить его из проверки.

```typescript
// Вариант 1: Исключить маршрут из CSRF проверки
app.use('/api', (req, res, next) => {
  if (req.path === '/csrf-token') return next();
  return csrfProtection(req, res, next);
});
app.get('/api/csrf-token', getCsrfToken);

// Вариант 2: Переместить маршрут перед middleware
app.get('/api/csrf-token', getCsrfToken);
app.use('/api', csrfProtection);
```

## 🟠 ВЫСОКИЙ ПРИОРИТЕТ (5)

### PERF-004: statusCounts не мемоизирован в PostsList
**Файл:** `src/components/PostsList.tsx` (строки 81-87)  
**Влияние:** Излишняя нагрузка при большом количестве постов. При 100+ постах и частых ре-рендерах может вызвать лаги.  
**Описание:** Объект statusCounts пересчитывается при каждом рендере, выполняя 4 фильтрации массива постов.  
**Решение:** Обернуть statusCounts в useMemo с зависимостью от posts.

```typescript
const statusCounts = useMemo(() => ({
  all: posts.length,
  new: posts.filter(p => p.status === 'new').length,
  approved: posts.filter(p => p.status === 'approved').length,
  published: posts.filter(p => p.status === 'published').length,
  rejected: posts.filter(p => p.status === 'rejected').length,
}), [posts]);
```

### BUG-005: Нет обработки ошибки при отсутствии CSRF токена
**Файл:** `src/api.ts` (строки 68-70)  
**Влияние:** Бесполезный запрос к серверу, который гарантированно будет отклонён. Лишняя нагрузка на сеть.  
**Описание:** Если fetchCsrfToken() возвращает null, запрос всё равно отправляется без токена и гарантированно получит 403.  
**Решение:** Проверять результат fetchCsrfToken() и показывать ошибку пользователю, если токен не получен.

```typescript
if (!['GET', 'HEAD', 'OPTIONS'].includes(method) && !csrfToken) {
  const token = await fetchCsrfToken();
  if (!token) {
    return {
      success: false,
      error: {
        code: 'CSRF_TOKEN_ERROR',
        message: 'Не удалось получить CSRF токен. Обновите страницу.',
      },
    };
  }
}
```

### PERF-005: Math.random() в генерации моковых данных
**Файл:** `src/store.ts` (строки 39, 44, 88-91)  
**Влияние:** Непредсказуемость моковых данных затрудняет тестирование и отладку. Каждый запуск даёт разные данные.  
**Описание:** В store.ts и webStore.ts всё ещё используется Math.random() для генерации моковых данных.  
**Решение:** Использовать детерминированные значения или фиксированный seed для генерации моковых данных.

```typescript
// Вместо Math.random() использовать индекс:
const mediaType = mediaTypes[i % mediaTypes.length];
const status = statuses[i % statuses.length];
const daysAgo = i % 7;
```

**Описание:** В api.ts CSRF токен получается один раз и хранится в переменной. Если токен истекает (через 1 час), запросы будут отклонены.

```typescript
// При получении 403 попробовать обновить токен:
if (response.status === 403 && data.error?.code === 'CSRF_TOKEN_INVALID') {
  csrfToken = null; // Сбросить старый токен
  await fetchCsrfToken(); // Получить новый
  // Повторить запрос
}
```
